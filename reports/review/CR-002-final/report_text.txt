Abstract
FrutaMIDI is a USB MIDI controller that sends notes when a user touches conductive
objects wired to a Raspberry Pi Pico and an Adafruit MPR121 capacitive sensor module,
built on a breadboard or on a single-sided home-etched PCB (v1.2). This report collects
the requirements, decisions, interfaces, analyses and host tests for FrutaMIDI v1.2. Version
1.2 (change request CR-002) replaces the electrode series resistors by pulse-rated parts lying
flat. By analysis of the design files, a4 kVcontact discharge should then neither arc across
a resistor nor exceed its pulse rating; this has not been tested. A manager PCB design
review then widened the JP1 solder-jumper gaps, enlarged the screw-terminal pads, tied the
potentiometer tabs to AGND and added a 100nF wiper filter (ADR-021). Section 12 lists
the changes since the V1_BASELINE release. Every number is copied from a cited project
file with its label.No part of the hardware has been built or measured: analyses,
simulations, design-rule checks and host tests are not hardware validation, and the physical
validation plan in Section 10 lists what remains to be measured.

1 Introduction and scope
FrutaMIDI is a USB MIDI controller that turns touches on conductive objects (fruit, plants,
water) into MIDI notes. It uses a Raspberry Pi Pico board and an Adafruit MPR121 break-
out (product 1982). The project continues an existing repository (v1.0.0 released) and covers
two builds: a solderless breadboard and a single-sided PCB for home etching, now at label
“FrutaMIDI v1.2”[management/DECISIONS.md](ADR-000; ADR-019 D-2 supersedes the “v1.1”
label of ADR-008). Version 1.2 is the result of change request CR-002[changes/CR-002.md]; the
changes since the V1_BASELINE release are listed in Section 12.
1.1 Scope
•In scope: electronics design (KiCad, generated by scripts), Pico firmware, the browser
sampler (docs/index.html), host tests, user documentation and this report[CLAUDE.md].
•Out of scope: ordering parts, flashing or powering hardware, and any physical mea-
surement. Hence every[PHYSICAL]requirement is at most PARTIAL or NOT RUN
[management/REQUIREMENTS.md].
•Hosts: Windows 10, Windows 11 and macOS 12 or later (ADR-007 D-6).
1.2 Document conventions
•Every number carries one label:SOURCE,CALCULATION,SIMULATION,MEASURE-
MENTorASSUMPTION, and a citation in brackets to the repository file it is copied from.
•Status is reported only as PASS, PARTIAL, FAIL, BLOCKED or NOT RUN.
•Passing ERC, DRC or a compile is not hardware validation.

design file); on the component side the end-cap gap is estimated at 3.61mm or more for a hand-
fitted part within±0.25mm (CALCULATIONon anASSUMPTIONed cap length, T-073).
The J2 electrode pads sit 1.40mm from the GND edge track, an intentional spark gap that
diverts a strike to ground (ADR-020). Its protection against IEC 61000-4-2 contact discharge
at±4kV is an estimate resting onASSUMPTIONs (the pin limit is inferred from HBM 2kV;
the breakdown models and the pulse-rating proxy are assumed), not a pass (review finding F-
002[reports/review/72f67f0/findings.md]). Only an ESD-gun test can close it. At 8kV the
resistor rating is exceeded (R-006). The design is not evaluated for touching while connected to
mains-powered equipment (ADR-003, ADR-012, ADR-019).

electronics calculationssh sim/electronics/calc/run_all.sh.
•Report:sh reports/report/build.sh(regenerates the requirements table from the CSV,
then three pdflatex passes), or eng-toolslatex_buildwithreports/report/frutamidi_
report.tex.
