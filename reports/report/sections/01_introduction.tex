\section{Introduction and scope}
\label{sec:intro}

FrutaMIDI is a USB MIDI controller that turns touches on conductive objects
(fruit, plants, water) into MIDI notes. It uses a Raspberry Pi Pico board and an
Adafruit MPR121 breakout (product 1982). The project continues an existing
repository (v1.0.0 released) and covers two builds: a solderless breadboard and a
single-sided PCB for home etching, now at label ``FrutaMIDI v1.3''
\ev{management/DECISIONS.md} (ADR-000; ADR-023). Version 1.3 is the result of change
request CR-003 \ev{changes/CR-003.md}, which converts the board to surface-mount
parts for chemical etching at home; it is described in Section~\ref{sec:cr003}.
Version 1.2 (CR-002, \ev{changes/CR-002.md}) was the through-hole board. The
changes since the V1\_BASELINE release are listed in Section~\ref{sec:changes}.

\paragraph{How to read this report.} Section~\ref{sec:cr003} describes the current
v1.3 board: its geometry, BOM and cost, ESD analysis, review findings, first-build
measurements and requirement status. Sections~\ref{sec:architecture} to
\ref{sec:validation} were written for the v1.2 through-hole board and are kept for
traceability; the firmware, host software and pin map in them still apply
(REQ-031). Where they disagree with Section~\ref{sec:cr003} on the board, its parts
or its numbers, Section~\ref{sec:cr003} applies.

\subsection{Scope}
\begin{itemize}[noitemsep]
  \item In scope: electronics design (KiCad, generated by scripts), Pico firmware,
        the browser sampler (\nolinkurl{docs/index.html}), host tests, user
        documentation and this report \ev{CLAUDE.md}.
  \item Out of scope: ordering parts, flashing or powering hardware, and any
        physical measurement. Hence every \lbl{[PHYSICAL]} requirement is at most
        PARTIAL or NOT RUN \ev{management/REQUIREMENTS.md}.
  \item Hosts: Windows 10, Windows 11 and macOS 12 or later (ADR-007 D-6).
\end{itemize}

\subsection{Document conventions}
\begin{itemize}[noitemsep]
  \item Every number carries one label: \lbl{SOURCE}, \lbl{CALCULATION},
        \lbl{SIMULATION}, \lbl{MEASUREMENT} or \lbl{ASSUMPTION}, and a citation
        in brackets to the repository file it is copied from.
  \item Status is reported only as PASS, PARTIAL, FAIL, BLOCKED or NOT RUN.
  \item Passing ERC, DRC or a compile is not hardware validation.
\end{itemize}
