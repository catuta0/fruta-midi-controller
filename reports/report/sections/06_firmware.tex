\section{Firmware design and tests}
\label{sec:firmware}

Sources: \ev{reports/firmware/coverage.md} and the T-040 to T-043 handoffs in
\ev{management/handoffs/firmware-engineer/}.

\subsection{Design}
\begin{itemize}[noitemsep]
  \item One sketch \nolinkurl{firmware/FrutaMIDI/FrutaMIDI.ino} with host-testable
        header-only logic \texttt{fm\_*.h}: scales (\texttt{fm\_scales.h}, English
        names), button (\texttt{fm\_button.h}), debounce, aftertouch, potentiometer,
        non-blocking LED blinker (\texttt{fm\_blink.h}), MPR121 burst reads
        (\texttt{fm\_mpr121.h}).
  \item Pads: Note On at velocity 100 on channel 1 by default; Note Off always
        carries the stored note; debounce is a \qty{15}{\milli\second} lockout per
        pad.
  \item Aftertouch: Polyphonic Key Pressure 0--127 from delta 12--120; one 0 is
        sent before Note Off and on a fall to the floor (T-041).
  \item Scales: 6, Drum Rack (36--47, octave ignored) default; octave $-2..+2$ by
        potentiometer with 0.7-zone hysteresis.
  \item Shared notes (T-044, ADR-017): a reference count per note; Note On when the
        first pad takes a note, Note Off only when the last pad releases it,
        aftertouch is the maximum of the holders.
  \item Sensor health (T-044): 3 consecutive failed transactions, or a changed ECR
        read-back (every \qty{250}{\milli\second}), mark a sensor lost; its pads are
        released, the LED shows the fast error blink, and the sensor is restarted
        after more than \qty{2000}{\milli\second} (\lbl{SOURCE}
        \nolinkurl{fm_sensor_health.h}). \texttt{setClock(400000)} now follows every
        sensor \texttt{begin()} (F-006).
  \item Defect found (ADR-017): on an I\textsuperscript{2}C NACK the Adafruit
        library's \texttt{touched()} returns 0x0FFF, i.e.\ all 12 pads touched, so a
        lost sensor would have sent 12 Note Ons. The sketch now reads the status
        registers itself and checks the transaction result
        \ev{management/handoffs/firmware-engineer/T-044.md}.
  \item Button: long press $>$ \qty{800}{\milli\second} recalibrates (releases all
        notes, restarts sensors, 3 blinks); short press selects the next scale.
  \item LED patterns are non-blocking: pads stay live while the LED blinks (T-041).
        \texttt{startSensors()} still blocks the loop during a user-requested
        recalibration (kept by decision; duration to be measured). The automatic
        restart of a lost sensor also blocks it for 16.8--22.1\,ms (\lbl{CALCULATION}),
        at most once per $\ge$2\,s retry; REQ-016 lists this fault-path exception
        (ADR-018, review N-001).
  \item MPR121 configuration: AUTOCONFIG with USL/TL/LSL = 200/180/130 at design
        VDD 3.2\,V and SCTS = 0 (ADR-010, ADR-011, \lbl{SOURCE} MPR121 datasheet
        S-006); I\textsuperscript{2}C stays at \qty{400}{\kilo\hertz}; run-based
        burst reads (worst mask 42 bus bytes in 8 transactions, \lbl{CALCULATION})
        \ev{reports/systems/budgets.md}.
\end{itemize}

\subsection{Latency budget}
Budgets revision 5 (T-013, includes the ECR health poll) \ev{reports/systems/budgets.md}
\ev{sim/systems/budgets.out}, all \lbl{CALCULATION} for $C \le 100$\,pF at
\qty{400}{\kilo\hertz}: worst case 10.72\,ms (1 sensor) and 12.35\,ms (2 sensors)
against $\le$ 15\,ms; jitter 6.72\,ms and 8.35\,ms against $\le$ 10\,ms: PASS. A
re-touch of the same pad within the \qty{15}{\milli\second} lockout adds up to
\qty{15}{\milli\second}, giving up to 25.72\,ms (1 sensor); REQ-014 is stated for a
pad idle for at least \qty{15}{\milli\second}. At \qty{100}{\kilo\hertz} the jitter
(1 sensor) and both 2-sensor checks FAIL, so the bus stays at \qty{400}{\kilo\hertz}
(ADR-008).
