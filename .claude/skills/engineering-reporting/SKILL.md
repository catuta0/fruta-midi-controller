# Engineering reporting

- Short. Lead with status per requirement (ID · status · evidence path).
- Every number with unit and label. Separate facts (with evidence) from assumptions and open risks.
- Gate summary: what was done · status per requirement · numbers · open risks · decisions the user must take.
- Final report (LaTeX): requirements and verification status, architecture and decisions, interfaces, analyses (assumptions, sensitivity, convergence where applicable), review findings with dispositions, limitations, PHYSICAL validation plan (what to measure, how, pass criteria).
- Never write "ready", "validated" or "works" for hardware that has not been measured.
