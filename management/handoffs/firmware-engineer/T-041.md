## Changes
1. **Translation.** All comments and serial strings in the .ino were translated: `" NOT FOUND"`, `"Scale: "`, `"Octave: "` and the `#error` text. The scale names are now "Drum Rack (notes 36-47)", "Major pentatonic", "Minor pentatonic", "Major", "Natural minor" and "Chromatic". `DEVICE_NAME` "FrutaMIDI" is unchanged.
2. **Aftertouch floor.**
   - `pressure_should_send()` now always sends p = 0 when the last sent value was above 0, so 1 → 0 is sent.
   - `releasePad()` sends one AT 0 immediately before Note Off when the last sent value was above 0. This also covers `releaseAll()` on recalibrate.
   - With `SEND_AFTERTOUCH = false`, `lastPressure` stays 0, so no extra message is sent.
3. **M1 burst read.**
   - The per-pad `filteredData()`/`baselineData()` calls in the loop were replaced by `readSensorData()`. It makes 2 Wire transactions (filtered data from 0x04 + 2·lo, baseline from 0x1E + lo), with auto-increment and repeated start.
   - The bytes are decoded by `fm_mpr121.h`: filtered = LSB | (MSB & 0x03) << 8, baseline = byte << 2.
   - **Deviation from the brief.** Reading the whole sensor on every due loop is a fixed 42 bytes. That would make the 1-pad case slower than before (42 vs 9 bytes). The sketch therefore reads runs of sounding pads, merged across gaps of at most 1 electrode. Adjacent pads, and all 12 pads, take one run = 2 transactions. Pads at both ends (gap ≥ 2) take 2 runs.
   - `debugPrint()` (SERIAL_DEBUG only) still uses the per-electrode library calls, which makes it a cross-check on hardware.
4. **F-1/F-2.** `configureSensor()` runs after a successful `begin()` when AUTOCONFIG is on:
   - read ECR, then write ECR = 0 (stop mode)
   - AUTOCONFIG1 (0x7C) = 0x00
   - USL 0x7D = 201, TL 0x7F = 180, LSL 0x7E = 130
   - restore ECR (one auto-configuration run with these limits)
   - AUTOCONFIG0 (0x7B) is left at the library value.

## Library lines relied on (SOURCE, Adafruit_MPR121.cpp 1.2.1, `setAutoconfig`)
- `writeRegister(MPR121_AUTOCONFIG0, 0b00001011);` decodes as FFI 00, RETRY 00, BVA 10 (= CL of ECR `0b10000000 + 12`), ARE 1, ACE 1.
- `writeRegister(MPR121_UPLIMIT, 200);` / `writeRegister(MPR121_TARGETLIMIT, 180);` / `writeRegister(MPR121_LOWLIMIT, 130);`
- `begin()` starts with a soft reset (`writeRegister(MPR121_SOFTRESET, 0x63)`). The library never writes `MPR121_AUTOCONFIG1` (a test asserts this).
- `writeRegister()` saves ECR, clears it and restores it around every write except ECR and 0x73–0x7A. Writing ECR = 0 first therefore avoids one run-mode transition per write.

## Numerical findings (value unit LABEL)
- **Flash vs T-040 final** (MEASUREMENT): RP builds +344 … +384 bytes; leonardo 12496 → 13108 bytes (+612). RAM on the RP builds is unchanged; leonardo globals 1036 → 1034 bytes.
- **Leonardo stack** (CALCULATION): the aftertouch buffers (24 + 12 = 36 bytes) are on the stack in `loop()`, against 1526 bytes free.
- **I2C bit time at 400 kHz, data path only** (CALCULATION; 9 bits per byte, start/stop and software overhead excluded):

  | Case | Old path | New path |
  |---|---|---|
  | 1 sounding pad | 9 bytes = 81 bits = 202.5 µs | 9 bytes = 202.5 µs (same) |
  | 12 sounding pads | 108 bytes = 2430 µs, 24 transactions | 42 bytes = 945 µs, 2 transactions |

  - The worst case over all 4096 pad masks is 42 bytes (MEASUREMENT: exhaustive host test of the plan).
  - Under the byte-cost model the plan always matches an independent DP optimum and never exceeds the old 9 bytes per pad.
  - The systems figure of 3.00–3.83 ms for 12 pads includes software overhead per transaction. Going from 24 transactions to 2 should remove most of that overhead too (ASSUMPTION, not measured).
- **F-2 limits** (CALCULATION, AN3889 formula with truncation, from the rounded USL):

  | VDD | USL | TL | LSL |
  |---|---|---|---|
  | 3.3 V | floor(2.6/3.3 × 256 = 201.70) = 201 | floor(0.9 × 201 = 180.9) = 180 | floor(0.65 × 201 = 130.65) = 130 |
  | library (fixed) | 200 | 180 | 130 |
  | 3.10 V (electronics' lower case) | 198 | 178 | 128 |

  - Only USL changes at 3.3 V, by 1 count (0.5 %).
  - The library's 200 matches VDD = 0.7 / (1 − 200/256) = 3.20 V (CALCULATION).
  - Electronics reports 198/178/129 at 3.10 V. The difference in LSL (128 vs 129) comes from rounding: electronics derives it from the unrounded USL (198.19 × 0.65 = 128.8).

## Assumptions
- SCTS is bit 7 of AUTOCONFIG1 (0x7C), not of AUTOCONFIG0 (0x7B) as the brief said. In 0x7B, bits 7..0 are FFI, RETRY, BVA, ARE, ACE, which matches the library's comments for 0x0B. The 0x7C layout is from my knowledge of the MPR121 datasheet / AN3889; neither document is in SOURCES.md yet. After a soft reset 0x7C is already 0x00, so the explicit write documents and enforces SCTS = 0 and does not change the value (ASSUMPTION, to be confirmed by datasheet and read-back).
- Register auto-increment over 24 bytes in a single read is an ASSUMPTION. The library itself only relies on it for 2 bytes. Each burst fits the 32-byte AVR Wire buffer (SOURCE: avr Wire `BUFFER_LENGTH 32`).
- Filtered high-byte bits 7..2 are not part of the value. They are masked, unlike the library's `filteredData()`, which returns the raw 16-bit value. The two give the same result whenever those bits read 0 (host test over 50 random frames).
- VDD = 3.3 V nominal, as stated in the brief.
