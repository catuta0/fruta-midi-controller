## Part D — User manual draft (docs/manual/MANUAL.md)
**Output:** docs/manual/MANUAL.md (sha256 59b41f8324eb680e9e53d6a5d1450565d2369d77dc2089ae8699d22c5b022a60). Sections: what it does, setup, playing, scales, octave, recalibration, LED signals, troubleshooting, and a traceability table.

**Trace basis:** the committed firmware `git show e4668d4:firmware/FrutaMIDI/FrutaMIDI.ino`.
- The working-tree firmware is being refactored under T-040: it is uncommitted, `firmware-FrutaMIDI-FrutaMIDI.ino.lock` is held by firmware-engineer, and it adds the fm_*.h headers.
- I spot-checked the new headers. They keep the same user-visible constants: `BUTTON_LONG_MS = 800`, `POT_HYSTERESIS = 0.7f`, the same SCALES table, and aftertouch 0..127. This was a grep only, not a full re-trace, so the manual must be re-checked once T-040 is committed.

**Check:** `T-031_logs/check_links.py` gave "MANUAL.md: 18 local links checked; RESULT: PASS".

**Numerical findings**
- Pad-to-note table, CALCULATION. Formula: `noteForPad()`: root + 12·oct + steps[pad mod len] + 12·⌊pad/len⌋, clamped 0–127. Inputs: SCALES[] at e4668d4, octave 0. Computed with a Python reimplementation; the table is in MANUAL.md.
- Note range at octave −2…+2, CALCULATION: lowest 24, highest 99 (minor pentatonic). The 0–127 clamp is never reached.
- Long press > 800 ms (SOURCE); the manual states it as 0.8 s.
- Startup blinks 2 × 120 ms; scale blinks N × 90 ms; recalibration 3 × 60 ms; fast blink toggles every 100 ms; retry every 2000 ms. All SOURCE, from the firmware.

**Untraced or README-only claims in the manual** (kept, and marked as README in the traceability table)
1. Sampler pads on notes 36–47 and aftertouch opening the filter: README only, not traced to docs/index.html.
2. Flashing procedure, BOOTSEL drive behaviour and `.uf2` names: README only. The existence of the release files and the build configuration (e.g. the potentiometer disabled in the breadboard `.uf2`) cannot be traced here.
3. Troubleshooting advice to use a smaller object, keep cables apart, or use a nail or needle: physical advice copied from the README, not measured.

**Firmware behaviours I documented that the README does not mention** (traced; worth your review)
- Pads are not read while the LED blinks: `blink()` uses `delay()`. Selecting scale 6 makes about 1.08 s of ignored touches, CALCULATION 6 × (90 + 90) ms.
- A long press triggers while the button is still held.
