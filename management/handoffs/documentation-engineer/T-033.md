## (b) csv_to_table.py
- **Usage:** `python3 -I reports/report/scripts/csv_to_table.py [CSV] [OUT]`. Defaults: requirements/requirements.csv → reports/report/generated/requirements_table.tex.
- **Output format:**
  - A longtable with a repeating header and booktabs rules. Columns: ID | Requirement (bold title + statement) | Verification | Status | Evidence. All columns ragged-right.
  - Caption with `\label{tab:requirements}`.
  - A comment header with the source path, sha256 and status counts, and a status-count line under the table.
- **Escaping:**
  - LaTeX specials: `\ & % $ # _ { } ~ ^ < > |`.
  - `` `code` `` becomes `\texttt{}`, with break points after `/` and `_`.
  - A map of non-ASCII characters: → ≤ ≥ ≈ ± × · Ω µ ° ² … − § τ and nbsp.
  - Any other non-ASCII character makes the script fail, so a bad glyph cannot slip into the table.
- **Validation (exit 1 on error):** required columns present, no empty or duplicate id, status must be one of PASS/PARTIAL/FAIL/BLOCKED/NOT RUN.
- **First run** failed on purpose: "unsupported character '§'" on 5 lines and "'τ'" on 1 line. I added both to the map and reran.
